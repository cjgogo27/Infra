## 运行与问题

先完成 [最小训练实验](/Infra/labs/00-training/) 并读 [2.2 节](/Infra/02-training/02/)。本实验使用 CPU 合成数据。

~~~bash
python labs/accumulation.py
~~~

要验证的不是“梯度可以相加”这句口号，而是：不同 microbatch 含有不同数量的有效项时，怎样得到与完整 batch 相同的目标函数。

## 先手算一次

教学例：第一块只有 1 个有效项，平均 loss 为 10；第二块有 3 个有效项，平均 loss 为 2。全部有效项的平均值为：

~~~text
(1×10 + 3×2) / (1+3) = 4
错误的块均值平均：(10+2)/2 = 6
~~~

这两个目标函数对样本赋予不同权重，梯度也可能不同。若每块有效项数量相同，等权平均才与全局平均一致。有效项可能是样本、非 padding token 或动作元素，必须先定义清楚。

## 输出判读

| 输出字段 | 正确判读 |
| --- | --- |
| full_vs_weighted_max_error | 正确加权累积与完整 batch 的最大差异，应满足脚本断言容差 |
| wrong_mean_max_error | 故意平均块均值的错误方案与基线的差异，展示归一化错误 |
| tail_window_max_error | 最后不足额窗口按实际数量归一化后的差异，应满足断言 |

误差不必字面上等于零；浮点运算顺序可能影响末位。判断以脚本明确的容差和断言为准。错误方案在某些特殊数据上也可能偶然接近，因此既要读数值，也要解释目标函数。

## 验收

说明为什么有效 batch=b×D×A 只是计数公式，不能替代 loss 权重定义。把有效项数改成另一组，先预测权重，再运行。最后解释只有两块的尾窗口为什么不能仍盲目除以预设的四次累积。

本实验不验证 DDP/FSDP 的通信或分布式 loss 缩放。多卡时还要把跨 rank 的归约语义纳入推导。
