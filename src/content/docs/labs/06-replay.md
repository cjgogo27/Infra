## 同一份样本，逐层检查

| 字段 | 教学约定 |
| --- | --- |
| image | RGB、uint8、shape=[1,3,32,32]，仅元数据 |
| joint state | j1到j6固定顺序，6个关节，单位为弧度 |
| action | shape=[4,6]，4 步、每步6关节，绝对目标角，单位弧度 |
| observation_ms | 观测时刻，用now_ms−observation_ms计算观测年龄 |
| chunk_start_ms | 动作块起始时刻；本例拒绝起点已早于now_ms的动作块 |
| now_ms | 检查时刻 |
| 时间与期限 | 同一 monotonic 时钟；允许的年龄上限100 ms |

100 ms 是本实验的教学约定，不是机器人安全保证。来自不同设备的时钟不能只因单位都是毫秒就直接相减；真实系统需要明确同步与时间映射。此处有意使用同一时钟来隔离接口问题。

正常样本observation_ms=1000、now_ms=1040，观测年龄40ms；stale用now_ms=1200产生200ms的过期样本。本例动作步长20ms，动作块校验是简化规则，不实现异步chunk的已执行前缀截取。

脚本检查正常 valid 样本以及 wrong_unit、wrong_shape、stale 三种故障。预期是正常样本通过，三种故障被拒绝，并在 JSON 中记录结果。拒绝意味着不进入后续动作发送，而不是强行把错误数据补齐。

## 读懂三种失败

- wrong_unit：形状可能正确，但动作意义不一致；不能只检查元素数。
- wrong_shape：关节维数或时间步数不符合契约；不能静默截断。
- stale：数据可能数值正确，但已不适合当前执行时刻；不能把过期动作排队继续执行。

## 验收与迁移

逐一指出故障发生在输入语义、结构还是时间有效性上。手算一个样本的年龄，解释为什么通过或拒绝；再说明即使全部检查通过，也不能证明策略会成功抓取。

完成后把这份 schema 连到自己的相机或策略时，必须重新确认动作坐标系、关节顺序、归一化和控制周期。本实验不替代模型质量评估、碰撞检测或控制器保护。
