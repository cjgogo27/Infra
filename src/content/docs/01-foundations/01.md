## 现场问题

算法同学说模型终于能抓杯子了，接到摄像头后，动作却晚了半秒；换到八张 GPU 上训练，速度也只提高一点。模型能力、训练速度和在线体验之间，缺了一层把部件接起来的工程。

> 带着问题读：为什么单个算子快两倍，机器人仍可能几乎没变快？

**基础设施（Infrastructure）、端到端（End-to-End）、服务目标（SLO）**

> **一句话听懂：Infra 让模型在给定资源里稳定、正确、及时地完成任务。**

先画两条线：训练是数据存储 → 解码采样 → CPU 内存 → GPU 前向 → 反向 → 梯度同步 → 参数更新 → 保存状态。推理是请求进入 → 排队 → 预处理 → GPU 执行 → 后处理 → 返回结果。机器人还要走到动作执行和下一帧观测。

算法关心学到了什么；Infra 还要解释为什么慢、为什么崩、能不能恢复、资源花在哪里。二者会互相影响：压缩输入可能提速，却改变模型看到的信息；增大批量可能提高吞吐，却改变优化过程或请求等待时间。

本书用 **LabBot** 作贯穿教学案例：带摄像头的桌面机械臂，输入图像、任务文字和关节状态，输出未来一段动作。它不是某个真实产品，也没有声称实测的硬件参数。配套代码先用小型网络演示测量方法，再把方法迁移到大模型。LLM 是大语言模型；VLM 加入视觉输入；VLA 进一步产生动作。结构不同，数据、显存、调度和通信问题依然存在。

用三句话约束优化：输入分布是什么；正确性门槛是什么；资源预算和性能目标是什么。例如“固定验证集质量不退化，在同一 GPU 上降低 batch=1 时的 p95 延迟”。p95 是 95% 样本不超过的延迟分位数，不是平均值。

**上下游影响：** 数据和质量门槛来自算法与产品，部署约束来自硬件与控制系统。Infra 交付可复核的配置、日志与对照结果。

**LabBot 落地：** 记录相机时间戳、策略开始和结束时间、指令发出时间。慢在解码时，改 Attention 内核就不一定有效。
