## 现场问题

训练突然消失，没有 Python traceback；另一回 GPU 很空闲，CPU 却跑满。只看模型代码，很难判断故障属于哪一层。

> 带着问题读：GPU 空闲时，增加 GPU 为什么可能无效？

**进程（Process）、线程（Thread）、主机与设备（Host / Device）、页锁定内存（Pinned Memory）**

> **一句话听懂：Python 在 CPU 上提交任务，GPU 异步执行；中间还有操作系统、内存和传输。**

进程拥有自己的地址空间，线程共享进程内存。DataLoader 常用多个子进程准备数据；Python、图像解码和底层数值库还可能有不同的线程池。工作进程越多，内存和调度开销也越大。

GPU 显存不是主机内存。数据通常先从磁盘进入 RAM，再传到 GPU。页锁定内存有助于异步传输，但占用不能被随意换出的主机 RAM。设置 non_blocking=True 不自动保证拷贝与计算重叠，还需要合适的内存、流和依赖。

先在 Linux 运行：
~~~bash
nvidia-smi
nvidia-smi topo -m
ps -eo pid,ppid,stat,%cpu,%mem,cmd --sort=-%cpu
free -h
df -h
~~~
前两项查看 GPU 进程和连接拓扑；后三项排查 CPU、RAM 和磁盘。GPU “利用率高”仅说明采样窗口里忙过，不保证算力已充分利用。

主机 OOM killer 终止进程时，Python 未必能写异常；先看退出码、调度器记录，再在有权限时看内核日志。GPU OOM 与 RAM 耗尽要分别定位。用作业调度器或持久会话运行远程任务，避免把 SSH 断开误判为训练崩溃。

**上下游影响：** CPU 核数、NUMA 位置和存储吞吐会限制 GPU 供给。

**LabBot 落地：** 多路相机解码与推理争抢 CPU 时，先看线程、队列和解码耗时，不要直接增加 GPU。
