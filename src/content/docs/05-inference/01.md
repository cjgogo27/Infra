## 现场问题

提示词越来越长，首字出来慢；并发越大，显存又很快耗尽。模型权重没变，为什么开销变了？

> 带着问题读：KV Cache 是否让长上下文的 decode 成本与历史长度无关？

**预填充（Prefill）、逐步解码（Decode）、键值缓存（KV Cache）、分页缓存（PagedAttention）**

> **一句话听懂：生成时复用历史 K/V 可以避免重复计算，但每个活跃序列都需要缓存空间。**

自回归模型先处理提示词，称为 prefill；随后逐 token 生成，称为 decode。历史 token 的 K/V 被保留，后续查询与它们交互。缓存避免重算历史 K/V，却不消除对历史上下文的注意力工作。

标准 Transformer 的简化 KV 预算为：
~~~text
KV 字节 ≈ 2 × 层数 × 活跃序列数 × 缓存长度
          × KV 头数 × 每头维度 × 每元素字节数
~~~
2 表示 K 和 V。教学配置 32 层、8 个 KV 头、头维 128、BF16、长度 4096、一个序列，约 512 MiB。GQA 的 KV 头数不等于 query 头数。滑动窗口、前缀共享、KV 量化以及其它注意力结构会改变估计，实际还含块分配开销。

分页缓存把逻辑连续序列映射到物理缓存块，减少大块连续预留带来的浪费，也便于动态管理。它不是把所有历史信息删掉，也不自动减少每个 token 的语义缓存需求。

FlashAttention 则主要通过分块与片上复用，避免显式写出巨大注意力中间矩阵；它与分页 KV 解决不同层面的问题。数学等价实现仍可能有浮点舍入差异。

**上下游影响：** 最大上下文、并发和输出长度直接约束容量。只估权重无法做服务容量规划。

**LabBot 落地：** VLA 若采用自回归动作 token，可涉及类似缓存；连续动作回归或 diffusion head 不应生搬 LLM 的逐 token 模型。

KV Cache 是否让长上下文的 decode 成本与历史长度无关？

不是。它避免重复构造历史 K/V，但新 query 通常仍要访问可见历史，缓存占用和注意力成本仍受长度影响。
