## The engineering problem

One person suggests a CUDA rewrite; another suggests a new data format. Both might help, but neither has evidence showing where time goes.

> Keep this question in mind: Why can summed CUDA durations exceed wall-clock time?

**Profiling · Critical path · Warm-up**

> **In one sentence: A profiler lays out execution and waiting so an optimization becomes a testable hypothesis.**

First measure a steady baseline without a profiler, then capture a short sample. Profiling adds overhead, especially with shapes, stacks, or detailed memory recording. Profiled throughput should not be presented as production throughput.

PyTorch Profiler connects PyTorch operations to device kernels. Nsight Systems shows CPU, CUDA, stream, and communication timelines. Nsight Compute investigates memory and execution behavior in selected kernels. Start globally before drilling into an unimportant hotspot.

CUDA is asynchronous: Python may return while the GPU is working. Synchronize at interval boundaries when measuring a whole batch with CPU wall time; use CUDA Events for device intervals. Synchronizing after every operator destroys concurrency and cannot characterize production overlap.

Ask what the CPU does before GPU gaps, whether many tiny kernels appear, whether transfers overlap compute, and whether communication tails block the next step. Summed operator durations may overlap; do not equate their sum with elapsed time.

**Upstream and downstream:** Record shapes and lengths to separate performance changes from traffic changes.

**LabBot in practice:** Mark decoding, normalization, encoder, action head, and command dispatch. Compare a complete slow request with an ordinary one.
