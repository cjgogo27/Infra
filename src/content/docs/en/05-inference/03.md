## The engineering problem

An INT8 file is smaller but no faster. Another INT4 model runs faster, yet the robot grasps less reliably.

> Keep this question in mind: Why is INT4 not necessarily faster than BF16?

**Quantization · Post-training quantization (PTQ) · Quantization-aware training (QAT) · Calibration**

> **In one sentence: Fewer bits help only when numerical error and hardware execution support the intended task.**

Uniform affine quantization can be written q=clip(round(x/scale)+zero_point), with x≈scale×(q−zero_point) after dequantization. Scale sets resolution and clipping sets range. Outliers may force poor resolution for most smaller values.

PTQ estimates quantization parameters from an existing model and representative data. QAT simulates quantization error during training. Per-tensor, per-channel, and per-group schemes trade accuracy, metadata, and hardware support. Weight, activation, and KV quantization are distinct choices.

W4A16 commonly means four-bit weights and sixteen-bit activations, not that every operation runs directly as four-bit integer arithmetic. Expensive dequantization, unsupported kernels, or dominant launch overhead can prevent smaller weights from improving latency.

Calibration should cover actual lengths, image lighting, tasks, and action ranges. A convenient random set does not establish production quality. Inspect layer errors and then task metrics. Language tasks may use perplexity or benchmark scores; action models need trajectories, success rates, and failure analysis.

**Upstream and downstream:** Backend dtype/layout/operator support constrains deployment. Another GPU may change the benefit.

**LabBot in practice:** Test keeping a sensitive action head at higher precision while quantizing the large backbone, using the same validation episodes. This is a hypothesis, not a universal VLA recipe.
