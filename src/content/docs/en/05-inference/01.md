## The engineering problem

Longer prompts delay the first token, and greater concurrency fills memory even though weights have not changed.

> Keep this question in mind: Does a KV cache make decode cost independent of history length?

**Prefill · Decode · KV cache · PagedAttention**

> **In one sentence: Caching historical keys and values avoids recomputation, but active sequences consume cache capacity.**

Autoregressive inference first processes a prompt—prefill—then generates iteratively—decode. Historical keys and values are retained for future queries. Caching avoids rebuilding them, not the work of attending to visible history.

A simplified standard Transformer budget is:
~~~text
KV bytes ≈ 2 × layers × active sequences × cached length
           × KV heads × head dimension × bytes per element
~~~
The factor two covers K and V. A teaching configuration with 32 layers, eight KV heads, head dimension 128, BF16, length 4096, and one sequence uses about 512 MiB. GQA has fewer KV heads than query heads. Sliding windows, shared prefixes, KV quantization, other Attention structures, and block overhead change actual usage.

Paged caches map logically contiguous sequences into physical blocks, reducing waste from large contiguous reservations and supporting dynamic allocation. They do not simply delete history or inherently eliminate semantic cache requirements per token.

FlashAttention instead emphasizes tiling and on-chip reuse to avoid materializing large intermediate Attention matrices. It addresses a different layer of the problem. Mathematically equivalent implementations may still differ in floating-point rounding.

**Upstream and downstream:** Maximum context, concurrency, and output length constrain capacity. Weight size alone is insufficient for serving plans.

**LabBot in practice:** Autoregressive action-token VLAs may use similar caching. Continuous regression or diffusion heads should not automatically inherit an LLM token-by-token model.

Does a KV cache make decode cost independent of history length?

No. It avoids reconstructing historical K/V, but new queries generally still access visible history. Memory and Attention costs remain length-dependent.
