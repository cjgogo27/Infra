## The engineering problem

A single matrix is too large, or the model has too many layers. Sharding stored state is not enough; computation itself needs partitioning.

> Keep this question in mind: With TP=2, PP=2, DP=2, microbatch=1 and four accumulation steps, what is effective batch?

**Tensor parallelism (TP) · Pipeline parallelism (PP) · Context parallelism (CP) · Expert parallelism (EP)**

> **In one sentence: Model-parallel cards cooperate on one sample; data-parallel replicas process different samples.**

TP splits within-layer computation. A linear layer can partition output features, compute partial outputs, and exchange them when later operations require it. Communication may occur every layer, making fast interconnect domains preferable to arbitrary free cards.

PP assigns consecutive layers to stages and streams microbatches through them. Startup and draining leave idle stages—the pipeline bubble. More microbatches may improve occupancy, but activation memory, scheduling, and update boundaries must remain consistent. Unbalanced stages also limit throughput.

CP partitions the context length and exchanges information needed for cross-partition Attention. EP distributes MoE experts; routing introduces all-to-all communication and imbalance. Their purposes and data flows differ.

Megatron Core supplies multiple parallelism components. Draw the groups first: with eight cards, TP=2, PP=2, DP=2, four model-parallel cards cooperate on one sample and there are two data replicas. More complex CP/EP layouts do not universally obey this simple grouping example.

**Upstream and downstream:** Parallelism changes checkpoints, randomness, batch accounting, and topology placement. Slow cross-node links can hurt frequent TP communication.

**LabBot in practice:** Establish DDP/FSDP measurements first. Add parallelism by identifying which tensor does not fit and which exchanges are frequent.
