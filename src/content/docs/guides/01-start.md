你不需要同时学会所有框架。先做到“知道数据和计算经过哪里”，再做到“能测量”，最后才是“能改进”。每周按 8–12 小时规划，这是建议安排，不是能力保证。

## 第一周：让单机系统透明

读第 1、2 章，运行实验 A 与 B。补齐 Python 上下文管理、迭代器、进程、Linux 内存和张量形状。遇到矩阵乘法时，先自己写出 [B,S,H] 经过线性层的输出形状。

验收：独立画出训练一步；解释主机 RAM 与显存；计算有效 batch；实际保存再恢复一次训练。交付环境信息、输出日志和一页问题记录。

## 第二周：从测量到一次改动

读第 4 章，比较 batch=1 与 batch=32 的延迟和吞吐。GPU 可用时记录峰值显存并导出 profiler trace；无 GPU 时只讨论 CPU 测量，不能推断 CUDA 性能。

验收：指出证据中的一个瓶颈，给一个改动假设，完成同输入、同设备的前后比较。提速失败也要保留结果。

## 第三周：理解多卡与部署

读第 3、5 章。两张 GPU 可跑实验 C；没有则手算通信与分片生命周期。用官方教程选择一个后端练习导出，先核对结果，再计时。不要为了覆盖所有工具而同时安装整套 CUDA 生态。

验收：说明 DDP 与 FSDP 的显存差别、TP 与 DP 的批量区别、prefill 与 decode 的瓶颈差别，以及量化的质量门槛。

## 第四周：迁移到具身系统

读第 6 章，选开放视觉模型或策略做离线输入输出回放。明确图像格式、动作定义和时间戳；建立端到端延迟表。实际机器人不是完成入门项目的前提。

验收：按附录项目模板提交代码、原始结果、正确性验证、一次负结果与局限。面试时能在三分钟内讲清“哪里慢、怎么知道、改了什么、代价是什么”。

## 一天内要面试

先读 1.1、1.3、1.4、2.2、3.1、3.2、4.1、5.1、6.1。只读场景、术语与第一条解释，然后完成附录口头自测。这个路线帮助建立语言，不等同于已有分布式工程经验。
