## 现场问题

一次简单归一化启动了多个内核、写出了多个中间张量。你想把它们融合，但不能只测一个刚好整除的输入。

> 带着问题读：为什么自定义 kernel 不能只和一个随机输入比较？

**内核（Kernel）、合并访存（Coalescing）、融合（Fusion）、边界掩码（Mask）**

> **一句话听懂：写内核是在安排并行计算与数据搬运，正确处理边界和数值同样重要。**

CUDA 需要理解 grid、block、thread、warp、寄存器和共享内存。Triton 语言通常以一块元素为单位表达并行计算，编译器负责部分映射，但不意味着无需考虑访存、布局和资源占用。

向量加法的 Triton 思路是：每个 program 取得一段索引，检查索引小于元素总数，带 mask 读取 a 和 b，相加，再带 mask 写出。没有边界 mask，最后一块在长度非整除时就可能越界。教程可从官方 vector add 开始，再学 softmax 和矩阵乘法。

融合减少中间结果写回和 kernel 启动，比如把逐元素缩放、偏置和激活合并。但融合过大可能增加寄存器压力、降低并发，或者妨碍成熟库选择更快的矩阵乘法内核。融合不是越多越好。

验证至少覆盖小尺寸、大尺寸、非整除长度、不同 dtype、极值与 NaN 约定。浮点计算顺序改变会产生误差，要按用途设定绝对与相对容差。只比较平均误差可能掩盖少数极端错误。

这里的 **Triton 语言** 用来写 GPU kernel；**NVIDIA Triton Inference Server** 是服务部署框架。两者同名但职责不同。TensorRT Plugin 则是给 TensorRT 增加自定义算子实现，还需声明支持的类型、形状和序列化行为。

**LabBot 落地：** 先从已确认占时较高的预处理或小动作头入手，保存正确性对照和不同形状的性能曲线，再讨论“加分项经验”。
