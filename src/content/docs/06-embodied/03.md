## 现场问题

GPU 训练很快，整个 RL 迭代仍慢。仿真重置、渲染和数据复制占去了大部分时间，有些环境还不断异常退出。

> 带着问题读：提高并行环境数为什么可能降低有效训练效率？

**环境采样（Rollout）、并行环境（Vectorized Environments）、策略滞后（Policy Lag）**

> **一句话听懂：机器人 RL 的 Infra 同时管理环境、策略和数据，新鲜样本比忙碌 GPU 更重要。**

一次循环包含观测、推理、环境步进、奖励、终止重置、轨迹整理和参数更新。视觉环境可能被渲染限制；复杂接触可能被仿真限制；跨设备复制也可能成为瓶颈。按环境步数/s 和有效样本数/s 统计，再看训练 tokens/s。

并行环境提高吞吐，但增加状态、渲染缓冲和轨迹存储；重置耗时不齐会造成负载不均。数据按环境和时间组织，区分正常终止与时间截断，正确构造 bootstrap 和 mask，否则速度提升可能伴随错误学习信号。

异步 rollout 让采样与训练重叠，但采样策略可能落后于当前策略。记录策略版本与滞后范围，按算法要求控制数据新鲜度。不能把所有旧轨迹都视为可直接用于任意 on-policy 更新。

稳定性包括 NaN、梯度爆炸、奖励异常、环境卡死和资源泄漏。异常前保存配置、seed、环境编号、样本摘要和版本，才能重现。只重新启动任务而不保留证据，很难说明故障已修复。

**上下游影响：** 增大环境并行度会改变采样分布和优化配置；改变仿真精度也可能改变任务物理，不能只比较速度。

**LabBot 落地：** 分别测无渲染状态环境与带视觉环境，判断渲染成本。把任何简化都写入实验记录，并重新评估策略质量。
