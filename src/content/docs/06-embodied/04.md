## 现场问题

你想用一段项目经历证明能够胜任岗位，但“调了几个参数，速度快了”很难让面试官判断你解决了什么问题。

> 带着问题读：如果一个优化没有提速，项目是否就没有价值？

**延迟预算（Latency Budget）、消融比较（Ablation）、回归验证（Regression）**

> **一句话听懂：有价值的优化项目是完整证据链：问题、定位、改动、结果和失效边界。**

给 LabBot 画时间线：曝光 → 解码 → 状态对齐 → 预处理 → 编码器 → 策略/动作头 → 后处理 → 通信 → 执行。教学预算可以暂设总计 100 ms，但它不是任何真实机器人的安全保证或实测指标；实际门槛应由控制任务定义。

不要把各阶段平均值相加当作 p95。尾部事件可能相关，阶段也可能重叠，应测每个请求的完整时间。观测年龄（动作发出时距观测的时间）比单纯模型执行时间更接近闭环新鲜度。

一个可完成的实习准备项目是：先做单 GPU 小模型基准；定位一个真实热点；只改一项；保留同输入的正确性比较；报告 warm-up、p50/p95、吞吐和峰值显存；再把方法迁移到开放 VLA 或视觉模型。没有 GPU 时完成 CPU 实验和系统设计部分，不能把它写成 GPU 加速经历。

项目仓库应包含环境版本、配置、启动命令、原始结果、分析脚本和局限。更快但质量下降的结果同样可以展示，前提是诚实说明取舍。没有成功的优化，也可展示定位过程与负结果。

**上下游影响：** 部署更新需要回归测试和可回退的模型/预处理版本，系统接口要允许拒绝过期动作和处理超时。

**LabBot 落地：** 在离线回放、仿真和受控硬件测试三个层次逐步验证。模型服务不能代替控制器的限位、碰撞保护和停止机制。

从 [固定 CPU 部署实验](/Infra/labs/04-project/) 与 [LabBot 离线回放](/Infra/labs/06-replay/) 开始，先交付可复核的文件和故障记录，再考虑真实策略与机器人。
