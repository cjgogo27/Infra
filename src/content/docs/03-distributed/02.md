## 现场问题

显存大半被参数、梯度和 Adam 状态占据。你希望更多卡不只提速，还能帮忙装下模型。

> 带着问题读：为什么 FSDP 仍可能 OOM？

**完全分片数据并行（FSDP）、ZeRO、All-Gather、Reduce-Scatter**

> **一句话听懂：平时分片保管状态，计算时交换所需参数，以通信换显存。**

ZeRO 可按优化器状态、梯度和参数逐步分片理解。FSDP 的 fully sharded 模式也围绕状态分片和按需聚合，但 API 和细节不能简单等同。

直观地看一层：计算前 all-gather 参数，执行前向，按策略释放或重分片；反向再取参数；reduce-scatter 聚合并分发梯度。是否保留、何时预取取决于实现和配置。持久状态缩小，不代表瞬时峰值按卡数均分。

包裹粒度重要：整个模型一个大单元，可能瞬时聚合巨大参数集合；按 Transformer block 划分更易控制峰值和重叠；太细则有大量小通信。

FSDP2 使用组合式 fully_shard 和 DTensor 等机制，不能直接混用旧 FSDP1 包装器示例。实践从已安装版本的官方教程开始，记录精确版本。

**上下游影响：** 分片影响 checkpoint 与导出。汇总完整权重可能额外占 CPU RAM；网络较慢时，省显存可能牺牲速度。

**LabBot 落地：** 分片大语言骨干，不必把小动作头拆成大量小单元。先判断峰值来自持久状态还是视觉激活，后者可能更适合重算。

### 四张卡、两层参数：逐步跟踪状态

设两层参数为 W1、W2，**每层的参数数据各 4 MiB**；四卡平均分片，每卡各持有 W1 和 W2 的 1 MiB 分片。这个假设只算参数，不含梯度、优化器、激活和缓冲。DDP 每卡保留两层完整参数，共 8 MiB；分片模式平时每卡参数分片共 2 MiB。

| 时刻 | 每卡持久分片 | 临时需要的完整参数 | 动作 |
| --- | --- | --- | --- |
| 初始 | W1 的 1/4、W2 的 1/4 | 无 | 各卡准备不同数据 |
| W1 前向前 | 同上 | W1，4 MiB | all-gather W1 |
| W1 前向后 | 同上 | 按策略释放 W1 | 保存所需激活 |
| W2 前向前 | 同上 | W2，4 MiB | all-gather W2 |
| W2 反向 | 同上 | W2，必要时重新聚合 | 算梯度，reduce-scatter 梯度 |
| W1 反向 | 同上 | W1，必要时重新聚合 | 算梯度，reduce-scatter 梯度 |
| 更新 | 各自分片 | 不要求整模型常驻 | 更新各自负责的状态 |

这里选择“前向后重分片”的教学策略，具体实现可保留参数、预取下一层，或者复用存储。**2 MiB 是持久参数分片，不是显存峰值。** 如果完整参数缓冲与持久分片同时存在，临时空间还要计入；预取两层时还可能同时存在两个完整缓冲。不能只用 8 MiB÷4 推断实际训练峰值。

手算验收：分别指出 DDP 的 8 MiB、分片的 2 MiB、当前层完整参数的 4 MiB 属于哪种量；解释为什么三者不能当成同一个“显存数字”。
