## 现场问题

你以为 CT、SFT 和 RL 只需换 loss，结果 RL 任务的大半时间都在等生成样本。

> 带着问题读：为什么 SFT 很快的框架跑 RL 却慢？

**继续训练（Continued Training）、监督微调（SFT）、强化学习（RL）**

> **一句话听懂：CT 常继续学习数据，SFT 学示范答案，RL 还组织采样、奖励与更新的循环。**

CT 缩写因团队而异，本书按 continued training 理解，面试时先确认。语言模型继续预训练常做下一 token 预测；SFT 使用指令和目标响应，通常要明确哪些 token 参与 loss，例如只计算 assistant 响应并排除 padding。

一份 batch 不只是字符串：还有 token IDs、attention mask、labels，有时包括图像和样本权重。变长样本 padding 浪费算力；packing 拼接样本可提高有效 token 比例，但必须处理边界和注意力隔离，防止无关样本互相泄露信息。

LLM RL 先用策略生成响应，计算奖励及参考策略或价值相关量，再更新策略。PPO 常有 critic，GRPO 等方法不一定有独立 critic。不能把一个算法的组件当成所有 RL 的必备项。采样与更新的显存、批量需求不同，更新后还需要同步推理端策略权重。

**上下游影响：** 长度分布决定负载均衡；奖励服务会产生等待；tokenizer 或模板不一致会破坏比较的意义。

**LabBot 落地：** 模仿学习可直接使用离线观测—动作对；机器人 RL 还涉及环境步进、重置与奖励计算。除了 token/s，要看有效环境步数/s。

先用一个小 batch 过拟合，确认样本、mask 和 loss 对齐，再开始提速。否则系统可能只是在更快地训练错误目标。
