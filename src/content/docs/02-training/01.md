## 现场问题

你以为 CT、SFT 和 RL 只需换 loss，结果 RL 任务的大半时间都在等生成样本。

> 带着问题读：为什么 SFT 很快的框架跑 RL 却慢？

**继续训练（Continued Training）、监督微调（SFT）、强化学习（RL）**

> **一句话听懂：CT 常继续学习数据，SFT 学示范答案，RL 还组织采样、奖励与更新的循环。**

CT 缩写因团队而异，本书按 continued training 理解，面试时先确认。语言模型继续预训练常做下一 token 预测；SFT 使用指令和目标响应，通常要明确哪些 token 参与 loss，例如只计算 assistant 响应并排除 padding。

一份 batch 不只是字符串：还有 token IDs、attention mask、labels，有时包括图像和样本权重。变长样本 padding 浪费算力；packing 拼接样本可提高有效 token 比例，但必须处理边界和注意力隔离，防止无关样本互相泄露信息。

LLM RL 先用策略生成响应，计算奖励及参考策略或价值相关量，再更新策略。PPO 常有 critic，GRPO 等方法不一定有独立 critic。不能把一个算法的组件当成所有 RL 的必备项。采样与更新的显存、批量需求不同，更新后还需要同步推理端策略权重。

**上下游影响：** 长度分布决定负载均衡；奖励服务会产生等待；tokenizer 或模板不一致会破坏比较的意义。

**LabBot 落地：** 模仿学习可直接使用离线观测—动作对；机器人 RL 还涉及环境步进、重置与奖励计算。除了 token/s，要看有效环境步数/s。

先用一个小 batch 过拟合，确认样本、mask 和 loss 对齐，再开始提速。否则系统可能只是在更快地训练错误目标。

### 一份明确的 PPO 教学配置

以下固定为**机器人环境中的同步 PPO，actor 输出动作，critic 估计状态价值**。它是职责与数据流说明，**不是 verl、Isaac Lab 或其它框架可直接执行的配置，也没有 GPU 实测结果**。GPU_A/GPU_B 是逻辑资源池，不代表所选模型必然装得下；小模型也可在 CPU 上练习数据流程。

~~~yaml
example: synchronous_robot_ppo
trainer_pool: GPU_A
rollout_pool: GPU_B
environments: 8
steps_per_environment: 32
samples_per_iteration: 256
minibatch_size: 64
update_epochs: 4
sampling_policy_version: v
publish_after_update: v_plus_1
~~~

8 个环境各采集 32 步，形成 256 个 transition；这不是 256 条完整轨迹。环境可在窗口内结束并重置，必须记录边界。这个简化配置每轮更新有 4×(256/64)=16 个 minibatch optimizer step，最后才发布新的采样版本。版本号对应一轮采样/更新协议，不必等于 optimizer step 计数。

~~~text
publish actor v -> rollout workers + environments
                -> observations/actions/rewards/old_log_probs/boundary_flags
                -> bootstrap values + advantages + returns
                -> trainer: PPO actor loss + critic loss
                -> 4 update epochs -> checkpoint v+1
                -> publish actor v+1 -> workers acknowledge -> next rollout
~~~

PPO 概率比要使用采样时的 old_log_prob，不能在更新后用新策略覆盖。环境奖励和 critic 各有职责，不能把 critic 当成奖励函数。上述机器人例子不含冻结参考语言模型；LLM PPO 若加入相对参考策略的 KL 项，还需增加参考策略评分以及外部奖励评分，不能把这个环境流程直接照搬成所有 LLM RL 配方。

验收：指出哪一步产生样本、哪一步改变参数、谁持有 old_log_prob，以及新权重什么时候允许用于下一轮采样。资源和故障职责继续见 [3.4](/Infra/03-distributed/04/)，环境边界与日志见 [6.3](/Infra/06-embodied/03/)。
