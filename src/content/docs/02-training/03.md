## 现场问题

GPU 每步开始前都有空白。换小模型没提速，换成显存中的随机数据却明显变快。

> 带着问题读：随机 GPU 张量为什么只能做诊断？

**数据加载器（DataLoader）、预取（Prefetch）、分片（Sharding）、数据泄漏（Data Leakage）**

> **一句话听懂：训练还要连续、正确地把下一批数据送到模型面前。**

把数据时间拆成读取、视频解码、增强、拼批和主机到设备传输。仅测 next(loader) 不一定看到全部开销：后台预取会隐藏工作，异步 GPU 同步又可能让之前的工作计入当前行。

建立三个基线：固定 GPU 张量测计算；内存数据加传输；真实存储加完整预处理。比较差异，再依次调整 worker 数、预取深度、页锁定内存和文件组织。过多 worker 可能耗尽 RAM、共享内存或文件句柄。

小文件增加元数据操作，分片存储改善连续读取却影响打乱和失败重试。视频压缩节约空间，但增加解码和随机跳帧成本。热缓存与冷缓存要分开报告。

分布式采样防止各 rank 重复读全部数据；epoch 变化时正确推进 shuffle 状态。长度分桶减少 padding，但要保留合理随机化并监测样本分布。

**上下游影响：** 数据格式由采集流程决定，不能为提速删除时间戳和坐标定义。GPU 很忙不代表数据正确。

**LabBot 落地：** 按 episode 划分训练验证，避免相邻帧跨集合泄漏。检查图像、关节和动作的时间对齐，确定标签是当前动作还是未来一步，先可视化完整样本再提速。
