## 现场问题

小显卡放不下大 batch，你缩小批量再累积梯度，训练能跑了，但更新幅度异常。

> 带着问题读：四卡每卡 2 个样本，累积 8 次，有效批量是多少？

**反向传播（Backpropagation）、自动混合精度（AMP）、梯度累积（Gradient Accumulation）**

> **一句话听懂：小批次梯度可以合成一次更新，但计数、缩放和同步必须一起算对。**

一次更新包括清梯度、前向、loss、反向和 optimizer step。梯度会累加到 .grad，不清理会带入上次更新；每个 microbatch 都清理又无法累积。

每卡 microbatch=b、数据并行副本=D、累积次数=A，等长等权样本的有效批量为 b×D×A。2×4×8=64；张量并行卡共同处理样本，不能再乘进去。等权平均 loss 常除以 A；各批有效 token 数不同，则应按有效 token 数加权，简单平均不是全局 token 平均。

AMP 让合适的算子使用较低精度，并保留数值敏感操作的较高精度。FP16 范围较小，常用 GradScaler；BF16 指数范围较大，通常不需要同样的缩放，但要硬件支持。梯度裁剪应在解除缩放之后、step 之前。

梯度累积不保证和一次大 batch 完全相同：BatchNorm、随机数、舍入和 loss 权重都会影响结果。学习率调度应按约定的 optimizer step 或 token 数推进。最后不足 A 个 microbatch 的窗口也要正确归一化。

**上下游影响：** 小 microbatch 降低激活峰值，却可能降低 GPU 效率；全局批量改变收敛。

**LabBot 落地：** 不同长度动作序列要明确按动作、轨迹还是 token 平均，优化不能悄悄改变 loss 语义。

动手验证：[加权梯度累积实验](/Infra/labs/05-accumulation/) 在 CPU 上比较完整 batch、2/6 个有效 token 的拆分和尾窗口，正确与错误实现都有数值证据。
